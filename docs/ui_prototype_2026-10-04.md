# 投与入力UIの試作

頻用5薬剤の入力、ポンプごとの操作、実施済みと予定の履歴を画面の上部にまとめました。臨床モデルや閾値を変更する作業とは分け、既存の計算修正を保持しています。

## 操作

1. フェンタニル、ヒドロモルフォン、モルヒネ、プロポフォール、レミマゾラムを固定表示。他の薬剤も展開できます。薬剤を選ぶだけでは記録されません。
2. ボーラス量または持続投与速度を入力し、「投与を記録」で保存。保存後は入力を空にし、連続クリックによる二重記録を防ぎます。量の増減ボタンで再入力できます。
3. 「実時刻・Now」は現在に追従。「5分前」「5分後」と正確な時刻入力も使えます。空の記録で実時刻へ切り替えると、開始の基準を現在の日時に設定します。既存履歴があれば開始を勝手に変えません。「経過分」では記録の基準を手動で指定します。
4. 基準時刻より後の入力は「予定」で保存。時刻が過ぎても自動で実施済みにはしません。履歴で実施を確認したとき、同じ記録の区分を変更します。

## 持続投与

- ポンプカードに、基準時刻で有効な速度、最終変更、予定の有無を表示します。番号はアプリ内の投与系列を区別する表示で、実機への接続を示しません。
- 「速度変更」「停止」「再開」は対象カードから行い、時刻と区分を確認して保存します。元の有限停止があれば速度変更でも維持し、必要なときだけ「停止するまで」へ変更できます。
- 「別ポンプ追加」は別系列の入力を開きます。同一薬剤がある場合は並行投与であることを明示し、独立した系列を作ります。
- 旧記録を選ぶと、その1件だけを新しい系列として扱います。ほかの未標識投与をまとめません。旧記録の区分は推測せず「旧記録・区分未設定」とします。
- 取消・戻るでは記録を変えません。編集途中に系列が変わった場合は保存を止め、対象の選び直しを案内します。

## 履歴と予測

実施済み、予定、区分未設定を分けて表示します。編集は元のIDを更新し、保存前まで元の記録を保持。削除と実施済みへの変更には確認があります。グラフをドラッグ中の変更は保存せず、確定時に保存し、取消時は全記録を元に戻します。

「予定を計算に含める」で予測を切り替えます。予定を外す際は、予定の速度変更・停止が区切った前の投与も入力された条件で再計算します。単に予定行を隠す処理ではありません。グラフと集計、参考アラートは同じ計算対象を使い、予定のマーカーも区別します。区分未設定の旧記録はどちらの計算にも含みます。

保存形式はschemaVersion 4。以前の1–3も読み込み、ID、単位、量、薬剤モデル、属性を保持します。新しい区分・系列・計算範囲・記録基準はlocalStorageと症例保存に含めます。旧アプリが新しい区分や系列を理解することまでは保証しません。従来どおり、保存できない状態は元の保存内容を上書きしません。

## 検証と限界

合成データで計算の回帰、並行投与の独立性、停止と再開、予定の計算除外、旧記録の読み込み、単位換算、繰り返し送信、取消・編集、日付変更を確認しました。PCと390px／320px幅を隔離Chromiumで検証しています。具体的な件数と証跡は作業結果に記載します。

今回の変更はローカル試作です。ポンプの実機接続、患者モニターとの照合、実施確認の自動化はありません。実施済み区分はユーザーの記録であり、アプリが投与の事実を確認した表示ではありません。入力例と画面画像は動作検証用の合成データです。数値計算の一致と、患者へのモデルの妥当性は別です。

初回表示と保存言語が未設定・不正な場合は英語です。EN／JPで選択し、明示的な保存済みの英語・日本語は維持します。ブラウザの言語やURLによって初期表示を自動変更しません。地域付きの保存言語も、対応する英語・日本語として扱います。
