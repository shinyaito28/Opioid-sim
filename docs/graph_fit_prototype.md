# 残る投与記録へ表示範囲を合わせる

基点は公開版c189879、作業ブランチはgraph-fit-to-dataです。本番へは反映していません。

## 原因と変更

投与の削除・編集後もplotStartを保持し、従来のX軸バーは症例開始からの右端だけを動かしていました。そのため、8時の投与を削除しても左端に7:55が残り、バーを動かしても古い開始位置が再び入り込みました。

X軸バーの近くに「全体に合わせる / Fit to data」を追加しました。押した時点で表示中の薬剤の残存記録を読み、最初の記録へ左端を寄せます。従来の最大5分の助走余白を使うので、8時・9時・10時のうち8時を削除した例では、左端は8:55になります。X軸バーも、この左端を保って表示幅を変更します。自動追従はせず、再度押すまで手動範囲を保持します。

表示範囲は原則2時間以上、最後の投与・速度変更・停止または有限持続終了後に1時間の予測を確保します。進行中の持続は架空の停止を追加せず、最後の記録から有限の予測区間を表示します。既存の24時間上限内で調整するため、上限に近い記録では予測区間が短くなります。表示中の薬剤に記録がない場合は標準の0〜120分へ戻します。

投与時刻、量、持続速度、症例の時計基準、患者情報、モデル、元の保存データは書き換えません。変更は表示範囲とmanualRangeだけです。Fitは独立したUndo対象とし、削除・編集と別に戻せます。Y軸の手動上限も維持します。既存の保存形式で表示範囲を保存・再読込できます。

- 全132テスト成功。残存投与、編集、Undo、有限・進行中持続、日付跨ぎ、空の記録、上下限、Xバーの左端固定、保存再読込、共通時刻のCp/Ce不変を確認しました。
- 独立したヘッドレスEdgeの架空症例で18項目を確認しました。削除後7:55からFitで8:55、Xバーによる30分ズーム、最初の投与の時刻編集、Undo/Redo、名前付き保存症例の読込とページ再読込、記録ゼロ、有限・進行中持続、日付跨ぎと1440分上限を操作しました。
- PC1280px、768px、390px、320pxの英日表示で横はみ出しなし、Fitボタンは44px以上、X軸バーの操作幅は100px以上です。未処理のブラウザ例外はありません。
